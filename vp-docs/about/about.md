# 关于 WeMD

WeMD 的诞生源于对现有微信编辑器的三个不满：
1. **数据绑架**：大多数微信编辑器强制云同步，你的数据变成了它们的资产。
2. **排版割裂**：写作在 A 处，复制到公众号 B 处后样式全乱，需要二次调整。
3. **样式太丑**：有些在线微信编辑器的样式极其丑陋，让人不忍直视。

因此，WeMD 确立了两大核心原则：

## Local First
**Local First** 不仅仅是「离线可用」。它意味着：
- **数据所有权**：文章存在你自己的设备和浏览器里，WeMD 不提供云端同步。
- **软件长存性**：写作、预览、排版、复制到公众号这些核心功能都不依赖 WeMD 的服务器；图片上传、AI 优化这类联网能力例外，服务不可用时它们也会不可用（个别主题里的装饰小图也来自 WeMD 的图片服务）。
- **隐私**：默认情况下，你的文章草稿不会经过 WeMD 的服务器。只有主动使用 AI 优化时，选中的内容才会发送给你自己配置的 AI 服务商。

三种存储方式的实际行为：

- **桌面版**：WeMD 直接读写你选择的本地文件夹，文章就是硬盘上的 Markdown 文件。
- **网页版 · 本地文件夹**：通过 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_Access_API) 让浏览器直接读写你授权的文件夹。
- **网页版 · 浏览器存储**（默认）：文章存在当前浏览器的 IndexedDB 里，换浏览器或清除站点数据就看不到，需要定期导出备份。

## 只为公众号生态设计
其他的编辑器是「通用的」，而 WeMD 是「专用的」。公众号编辑器在粘贴时会过滤掉一部分标签和样式，WeMD 在复制这一步做了针对性处理：
- **内联样式**：复制时把主题 CSS 内联到每个元素上，并展开 CSS 变量，避免公众号丢掉 `<style>` 标签或 `var()` 之后样式错乱。
- **表单元素**：把勾选框转成对应的 emoji，因为公众号会过滤 `<input>`。
- **公式和图表**：容易出错的公式和 Mermaid 图表会在复制时转成图片。
- **表格**：按公众号的阅读宽度重新排版，可以选择横向滚动或内容区内自动换行。
- **外链**：可以开启「外链转脚注」，把正文里的外部链接收进文末脚注。
- **深色模式**：内置微信深色模式预览算法，尽量贴近实机效果。预览和真机之间仍可能有差异，具体说明见[微信深色模式预览算法](/reference/dark-mode-algorithm)。

## 支持 WeMD

WeMD 会继续保持免费、开源。WeMD 默认使用官方图床：图片上传到 WeMD 的官方服务，无需任何配置就能用；也可以在「图床设置」里换成自己的图床，见[配置图床](/guides/setup-image-hosting)。目前官方图床的免费存储空间逐渐吃紧，如果这个项目对你有所帮助，欢迎通过微信或支付宝自愿支持。收到的支持将优先用于图片存储、带宽及项目持续维护。
